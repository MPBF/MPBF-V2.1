# نتائج قياس البحث في تاريخ الإنتاج

## النتيجة والقرار

جرى القياس على PostgreSQL 16.10 محلي وببيانات اصطناعية فقط، على أرشيفين
بحجم 10,000 و100,000 أمر وسند، مع ثلاثة رولات لكل أمر، بالإضافة إلى بيانات
اختبارات دورة الإنتاج. لم تُستخدم بيانات العملاء أو قاعدة التطبيق أو قاعدة
الإنتاج المنشورة في التجارب.

**لم يُغيَّر استعلام التطبيق في `server/production/history.ts`.** البديلان
المختبران بلا تغيير مخطط حسّنا حالات محددة، لكنهما أبطآ حالات أخرى بوضوح؛
لذلك لا يصح تعميم أي منهما بوصفه تحسيناً آمناً. هذه نتيجة بحث وقياس، وليست
ادعاءً بأن البحث المنشور أصبح أسرع.

لم تُنشأ فهارس أو إضافات PostgreSQL أو أعمدة أو جداول بحث جديدة. يلزم الحصول
على موافقة مستقلة قبل **أي فهرس أو تغيير مخطط، حتى للتجربة المحلية**، وموافقة
مستقلة أخرى قبل تغيير قاعدة الإنتاج المنشورة. لم تُطلب أو تُفترض هذه الموافقة
ضمن تنفيذ القياس الحالي.

## المنهج

- `scripts/verify-production-history.ts`: إنشاء الأرشيف الاصطناعي والتحقق من
  الكميات الكاملة وسلامة صفحات التاريخ، ثم تشغيل مقارنة البحث عند طلبها.
- `scripts/production-search-experiments.ts`: نسخ SQL تجريبية محلية، خارج كود
  الخادم. مقارنة النتيجة الكاملة لكل سيناريو مع الاستعلام الحالي قبل اعتماد
  كل عينة زمنية.
- `scripts/production-read-plans.ts`: تشغيل
  `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` **على SQL البديل نفسه**، وليس على
  النسخة الأصلية تحت اسم البديل.
- `scripts/verify-production-search.ts`: بيانات حدودية اصطناعية في معاملة
  تنتهي بـ `ROLLBACK`، بما فيها السند متعدد البنود والبحث الحرفي.
- أدوات البحث والخطط تتحقق من اسم قاعدة الاختبار `factory_isolated_test`
  واتصال loopback قبل بدء التشخيص أو الكتابة التجريبية.

الأرقام التالية هي **وسيط خمس عينات** بالمللي ثانية، وتشمل قراءة الخدمة
ونقل النتائج إلى Node، ولا تمثل زمن المتصفح أو وعداً لأداء الإنتاج. لا تشمل
زمن إنشاء البيانات أو EXPLAIN. الخطط تؤخذ منفصلة بعد العينات، وتزيد كلفة
قياسها التفصيلية؛ لذلك لا تُخلط أزمنتها مع وسيط الخدمة.

الترتيب ثابت: الحالي ثم تقسيم الشروط ثم الفحص المترابط، داخل نفس أرشيف كل
تشغيل. القياس محلي ودافئ غالباً، وليس اختباراً لحمل متزامن أو ذاكرة تخزين
باردة. الخطط عند 100 ألف سجل سجلت صفراً لقراءات shared من القرص وكتابة temp
في عقد الجذر للسيناريوهات المعروضة. اختلاف اختيارات المخطط والذاكرة والتحميل
يفسر بعض التفاوت بين الحجوم؛ لا يُفترض نمو خطي أو زمن ثابت.

## البدائل

1. **الحالي:** شروط `OR` داخل اختيار معرّفات الصفحة، و`EXISTS` لبنود السند،
   ثم إسقاط التفاصيل والكميات لجميع بنود السند المختار.
2. **تقسيم الشروط (`split_or`):** فصل شروط البحث الخارجية إلى فروع `UNION`،
   لكل فرع نفس المرشحات والمؤشر وحد `limit+1`، ثم إزالة التكرار واختيار أعلى
   معرّفات الصفحة. تبقى التفاصيل خارج هذه الفروع. بلا فهرس جديد تزداد مسوح
   الجداول، خصوصاً عند البحث في الأوامر.
3. **الفحص المترابط للسند (`correlated_receipts`):** إضافة `OFFSET 0` داخل
   استعلام `EXISTS` التجريبي لمنع تحويله إلى مجموعة معرّفات مطابقة محسوبة
   مسبقاً. يتوقف مبكراً عند كثرة المطابقات الحديثة، لكنه يكرر عمليات البحث
   المفهرسة على جميع السندات عندما تكون المطابقات نادرة أو معدومة. لا يغير
   SQL الأوامر؛ أي فرق في قياس الأوامر لهذا البديل مجرد تفاوت قياس.

## ما تفسره خطط التنفيذ

- البحث الانتقائي الحالي في الأوامر مر على **100,026 صف أمر إنتاج** قبل
  إرجاع نتيجة واحدة. أخذت خطته المفصلة 381.916 ms وسجلت 601,868 إصابة
  shared-buffer. البحث الواسع وجد 51 مرشحاً مبكراً، وخطته 2.223 ms.
- بحث السند الواسع الحالي بنى مجموعة المطابقات عبر **100,026 أمر إنتاج
  و100,067 بند استلام**، رغم أن الصفحة تحتاج 51 مرشحاً فقط. خطته
  167.345 ms، منها كلفة البحث قبل إسقاط بنود الصفحة.
- تقسيم شروط الأوامر كرر المسوح؛ بلغت خطة البحث الانتقائي 875.527 ms
  و1,811,381 إصابة shared-buffer، دون فائدة تبرر اعتماده.
- الفحص المترابط جعل بحث السند الواسع 1.419 ms في EXPLAIN: فحص البنود
  المترابط تكرر 60 مرة فقط، لأن أرقام السندات المطابقة تجاوزت فحص البنود.
  هذا مختلف عن استرجاع بنود السندات المختارة في مرحلة الإسقاط النهائي.
- عند البحث الانتقائي، تكرر فحص البنود المترابط **100,066 مرة**، وأصبحت
  الخطة 669.260 ms مع 1,202,100 إصابة shared-buffer. البحث بلا نتائج كان
  702.826 ms. هذا هو سبب عدم اعتماد البديل رغم سرعته في البحث الواسع.

إصابات buffer هي عمليات وصول متكررة، وليست عدد كتل فريدة أو استهلاك ذاكرة.
حد الصفحة يحد النتائج والتفاصيل، لكنه لا يحد بالضرورة العمل اللازم لإيجادها.

## الحفاظ على الدلالات والخصوصية

التحقق المحلي نجح لكل البدائل في:

- العربية والإنجليزية ومطابقة حالة الأحرف الإنجليزية.
- التعامل الحرفي مع `%` و`_` و`\`، وعدم تحويل مدخل البحث إلى SQL.
- الأسماء المحفوظة والأسماء الحية عند غياب التنفيذ، وحقول اللقطة ذات `null`.
- أرقام أمر الإنتاج وأمر العميل والدفعة والسند، وملاحظات السند ومعرّفات البنود.
- إعادة جميع بنود السند، حتى عندما يطابق البحث بنداً واحداً فقط، دون تكرار
  السند عند مطابقة عدة بنود.
- بقاء كميات البنود نصوصاً عشرية، وعدم اقتطاع الكميات الكاملة حسب الصفحة.
- مرشحات الأمر والموقع والحالة والتاريخ، مع أيام الرياض.
- صفحات المؤشر ذات سجل واحد، وعدم التكرار أو الفقد، وتطابق `next` والنتيجة
  الكاملة مع الحالي.
- صلاحيات التاريخ الحالية عبر اختبارات دورة الإنتاج الأصلية.

سجلات المقارنة تحتوي أسماء سيناريوهات ثابتة وأزمنة فقط، والخطط تحتوي قائمة
مسموحة لأنواع العقد وأسماء جداول/فهارس الاختبار والأعداد والأزمنة والكتل.
لا تسجل SQL أو معاملات أو شروط الخطة أو عبارات بحث المستخدمين أو أسماء
العملاء أو نتائجهم. اختبارات الوحدة تتحقق من هذا الحذف ومن حارس البيئة
ومن تطبيق البديل قبل إضافة EXPLAIN.

## ما يحتاج موافقة مستقلة

التوصية التالية **تجربة محلية مقترحة لا تغيير معتمد**: قياس فهارس بحث
substring مناسبة مثل `pg_trgm`، مع فروع بحث تراعي الفصل بين الأسماء المجمدة
والحالية. لا تكفي إضافة فهرس واحد بصورة عمياء لأن الشروط تشمل جداول متعددة
و`COALESCE` وحقول JSON ومعرّفات محوّلة إلى نص.

قبل أي تجربة فهرسة، يجب عرض الفهارس/الإضافات المستهدفة ونطاقها للحصول على
موافقة. تشمل التجربة المعتمدة لاحقاً وقت البناء والحجم وكلفة الكتابة،
والبحث الانتقائي والواسع والعربي وبلا نتائج، مع بقاء جميع دلالات البحث.
لا تستنتج من نتائج التجربة المحلية صلاحية تغيير قاعدة الإنتاج المنشورة.
هذه الدراسة لا توصي بإضافة جدول بحث أو تغيير أنواع البيانات دون قياس
وموافقة منفصلين.

```sh
bash scripts/test-production-history-isolated.sh --large --search-experiments

npm run check
npm test -- --roots tests --runTestsByPath \
  tests/production-search-experiments.test.ts \

```

نجح تشغيل كل حجم مع 24 سيناريو تكامل PostgreSQL أصلية، إضافة إلى تحقق
دلالات البدائل والمقارنات. نجح فحص TypeScript و13 اختبار وحدة. النتائج
التفصيلية لهذا التشغيل محلية وغير متتبعة في Git تحت
`generated-artifacts/production-search/final-10k.log` و`final-100k.log`.

لم يتغير كود الواجهة أو الخدمة المنشورة، ولم تُشغّل نسخة التطبيق لأجل
هذه الدراسة؛ تحقق المتصفح للواجهة المسجلة الدخول ليس جزءاً من هذه النتائج.

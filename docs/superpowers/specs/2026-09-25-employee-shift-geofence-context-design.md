# عرض الوردية والنطاق الجغرافي للموظف

## الهدف والنطاق

- توضيح الوردية النشطة ومتطلبات نطاق الموقع داخل بطاقة الحضور في لوحة الموظف.
- يعرض الموظف اسم الوردية ووقتها وحالة النطاق ونصف قطره فقط؛ لا تُرسل إحداثيات مركز النطاق إلى المتصفح.
- لا يغيّر هذا العمل إعدادات الإدارة أو تسلسل إجراءات الحضور الحالي، ولا يضيف إسناد وردية مخصصًا لكل موظف.

## مصدر البيانات والعقد البرمجي

- توسّع استجابة `GET /api/self/attendance` بحقل موجود دائمًا باسم `activeShift` بدل إضافة طلب شبكة مستقل أو السماح للواجهة بقراءة `system_settings`.
- تكون قيمة الحقل `null` عند غياب الإعدادات أو فسادها أو عدم وجود وردية نشطة. وإلا يكون شكلها:

```ts
type ActiveShift = {
  id: string;
  name: string;
  startTime: string;
  endTime: string;
  geofenceStatus: "enabled" | "disabled" | "invalid";
  radiusMeters: number | null;
};
```

- يأتي `name` من الاسم العربي غير الفارغ، ثم الإنجليزي، ثم القيمة الاحتياطية «الوردية الحالية». تحفظ الأوقات بصيغة `HH:mm`. يكون `radiusMeters` رقمًا صحيحًا فقط عندما تكون `geofenceStatus` مساوية لـ `enabled`، ويكون `null` في الحالتين الأخريين.
- تتولى وحدة خادم واحدة قراءة `work_shifts` وتحليلها والتحقق منها وتحديد الوردية النشطة وإنتاج العرض الآمن. يستخدمها كل من `GET /attendance` و`POST /attendance` حتى لا يختلف العرض عن التحقق.
- يستبعد المحلل الوردية ذات وقت بداية أو نهاية غير صالح. النطاق المكتمل الصالح يتطلب خط عرض بين `-90` و`90`، وخط طول بين `-180` و`180`، ونصف قطر بين `20` و`5000` متر.
- يحدد الخادم الوردية النشطة حسب توقيت الرياض وبداية الوردية ونهايتها ونافذتي الحضور المبكر والخروج المتأخر، وتكون حدود النافذة مشمولة. تدعم النافذة العبور بعد منتصف الليل.
- عند تداخل ورديتين نشطتين، تفوز أول وردية حسب ترتيبها المحفوظ في مصفوفة `work_shifts`. يطبق `GET` و`POST` هذه القاعدة نفسها.
- بعد اختيار الوردية من القائمة كاملة، تكون حالة النطاق `disabled` إذا كان مفتاح التفعيل غير مفعّل، و`enabled` إذا كان مفعّلًا وإعداداته صالحة، و`invalid` إذا كان مفعّلًا لكن مركزه أو نصف قطره ناقص أو غير صالح.
- لا يمنع غياب وردية نشطة إجراءات الحضور، حفاظًا على السلوك الحالي. يطبق `POST` التحقق الجغرافي فقط عندما تكون حالة نطاق الوردية المختارة `enabled`.

## واجهة الموظف

- يضاف داخل بطاقة الحضور قسم صغير بعنوان «وردية اليوم».
- عند وجود وردية نشطة يظهر اسمها ووقتها بصيغة مثل: `الوردية الصباحية · 08:00–16:00`.
- عند تفعيل النطاق تظهر شارة واضحة «النطاق مفعّل» والنص: «يجب أن تكون داخل 200 متر لإتمام التسجيل».
- عند تعطيل النطاق تظهر شارة محايدة والنص: «لا يوجد تقييد جغرافي لهذه الوردية».
- عند كون إعداد النطاق مفعّلًا لكنه غير صالح تظهر شارة تحذير «إعداد النطاق غير مكتمل» والنص: «يرجى التواصل مع الإدارة»، من دون الادعاء بأن النطاق مطبق.
- عند عدم وجود وردية نشطة يظهر النص: «لا توجد وردية نشطة في الوقت الحالي» من دون تعطيل أزرار الحضور.
- تراعي الإضافة اتجاه RTL وأحجام الهاتف وسطح المكتب، وتستخدم الأنماط البصرية الحالية للوحة الموظف.

## الأخطاء والخصوصية

- يرفض الخادم التسجيل خارج النطاق برمز HTTP `403` وجسم `{ code: "OUTSIDE_GEOFENCE", message: string }`، وتتضمن الرسالة العربية اسم الوردية ونصف القطر المطلوب.
- يحفظ عميل API في الواجهة `status` و`code` مع الرسالة. عند `code === "OUTSIDE_GEOFENCE"` يعرض عنوان «تعذر تسجيل الحضور من هذا الموقع» مع رسالة الخادم، بينما تبقى أخطاء إذن الموقع وانتهاء المهلة والاتصال بصيغها الحالية.
- لا تعرض الواجهة المسافة الفعلية للموظف ولا الإحداثيات، ولا تعيد API الموظف مركز النطاق.
- لا يعاد تحميل بيانات اللوحة بعد محاولة رفضها النطاق؛ تبقى البيانات الحالية وتظهر رسالة الرفض حتى المحاولة التالية أو التحديث اليدوي.

## التحقق والاختبارات

- اختبار تحديد وردية نهارية ووردية ممتدة بعد منتصف الليل، مع نوافذ الحضور المبكر والخروج المتأخر.
- اختبار اختيار الوردية من القائمة كاملة قبل فحص تفعيل النطاق، بما في ذلك أوقات الورديات المتداخلة.
- اختبار حالات: نطاق مفعّل، نطاق معطّل، نطاق مفعّل بإعداد غير صالح، إعدادات غائبة أو تالفة، لا توجد وردية نشطة، وأسماء أو أوقات غير صالحة.
- التحقق أن استجابة الموظف لا تتضمن إحداثيات مركز النطاق.
- اختبار عرض اسم الوردية ووقتها وحالات النطاق وعدم وجود وردية، وعرض رسالة رفض النطاق بوضوح.
- تشغيل ملفات اختبار Jest مباشرة عبر `npx jest --runInBand <files>` لأن `package.json` لا يحتوي حاليًا على أمر `test`، ثم تشغيل `npm run check` و`npm run build`، مع توثيق أي عطل سابق غير متعلق بالميزة بصورة منفصلة.
- إجراء فحص يدوي لبطاقة الحضور على عرضي الهاتف وسطح المكتب.
